# AiScript スクリプト書式仕様書

## 1. 概要

AiScript は、自然言語で記述したプロンプトを Codex に渡し、プログラミング言語に似た制御構文で実行順序を制御するスクリプトである。

本仕様書は AiScript の書式と各構文の意味を定める。

| 書式 | 機能 |
| --- | --- |
| `<` ～ `>` | プロンプトの実行 |
| `if` | ファイルの存在に基づく条件分岐 |
| `for` | 整数範囲による繰り返し |
| `foreach` | 文字列の列挙、またはテキストファイルの各行による繰り返し |
| `session` | Codex セッションの共有 |
| `${name}` | プロンプト内の変数展開 |
| `//`、`/* ... */` | コメント |
| `writable` | Codex の書き込み先の追加 |
| `resetdir` | フォルダの作り直しと書き込み先の追加 |
| `delete` | ファイルまたはフォルダの削除 |

## 2. 基本書式

### 2.1 文字コード

スクリプト本体と `foreach` が読み込むテキストファイルには、同じ判定規則を適用する。

| ファイルの先頭 | 読み込み時の文字コード |
| --- | --- |
| UTF-8 BOM (`EF BB BF`) あり | UTF-8 |
| UTF-8 BOM なし | CP932（Windows の Shift_JIS） |

UTF-8 BOM なしのファイルを UTF-8 として自動判定することはない。UTF-8 で保存する場合は必ず BOM を付ける。

### 2.2 行とブロック

- 制御構文のヘッダ、`{`、`}`、プロンプト境界の `<`、`>` は、それぞれ独立した行に記述する。
- 構文行の前後の空白は無視する。インデントは任意である。
- プロンプト外の空行は無視する。
- 制御構文の本体は必ず `{` と `}` で囲む。複数の文を記述できる。
- プロンプト外に任意の自然言語を直接書くことはできない。

正しい例：

```text
if ( EXISTS "result.txt" )
{
    <
        結果を確認してください。
    >
}
```

誤った例（ヘッダと `{` が同一行）：

```text
if ( EXISTS "result.txt" ) {
}
```

## 3. プロンプトブロック

```text
<
    東京の人口を調べてください。
    結果を TOKYO.txt に保存してください。
>

<
    TOKYO.txt を読み、内容を要約してください。
>
```

- `<` で開始し、`>` で終了する。境界記号は単独行とし、前後に空白を置いてもよい。
- 各ブロックは独立したプロンプトを表す。
- 各行の行頭空白を除去し、行末空白と改行を保持する。
- ブロック内部の `if`、`{`、`}`、`//`、`/* ... */` などは制御構文やコメントとして解釈しない。
- プロンプトブロックの入れ子は禁止する。単独行の `<` は内部に置けない。単独行の `>` は終了記号となる。
- 内容が空、または空白のみのブロックは構文エラーとする。

## 4. コメント

```text
// 1行コメント

/*
    複数行コメント
    この部分は実行されない。
*/

if ( EXISTS "result.txt" ) // ファイルがある場合だけ実行
{
    <
        result.txt を要約してください。
    >
}
```

- `//` から行末までをコメントとする。
- `/*` から `*/` までを複数行コメントとする。
- コメントはプロンプトブロックの外側でのみ有効。
- 引用符付きパスや文字列リテラルの内部では、コメント記号を通常の文字として扱う。
- コメントを除去した後も、構文要素の独立行の規則を満たす必要がある。

## 5. パスの記述

`EXISTS`、`foreach ... : FILE`、`delete`、`resetdir`、`writable` で使用するパスは次の形式で記述する。

```text
C:\temp\DATA.txt
"C:\My Data\DATA.txt"
"data\names.txt"
```

- 絶対パス、相対パスの両方を使用できる。
- 相対パスはスクリプトファイルが存在するフォルダを基準とする。
- 空白を含むパスは二重引用符で囲む。空白がない場合は引用符を省略できる。括弧など条件式の構文と紛らわしい文字を含む場合も引用符で囲む。
- パス内のバックスラッシュ `\` はエスケープ文字として扱わない。Windows のパスをそのまま記述できる。
- パス内では変数展開を使用できない。

## 6. if

### 6.1 基本書式

```text
if ( EXISTS "A.txt" )
{
    <
        A.txt の内容を調べてください。
    >
}
```

条件が真の場合だけブロックを実行する。偽の場合はブロック全体を飛ばし、後続の文へ進む。

### 6.2 条件式

使用できる原始条件はファイルの存在確認 `EXISTS` のみとする。`EXISTS` は通常ファイルが存在すれば真となる。ディレクトリの存在は真としない。

| 記号 | 意味 |
| --- | --- |
| `EXISTS path` | ファイルが存在する |
| `NOT` | 条件の否定 |
| `AND` | 両方の条件が真 |
| `OR` | いずれかの条件が真 |
| `( )` | 条件式のグループ化 |

演算子の優先順位は高い順に `NOT`、`AND`、`OR` とする。括弧で評価順序を変更できる。`AND` と `OR` は短絡評価を行う。

```text
if ( NOT EXISTS "A.txt" )
{
    <
        A.txt を作成してください。
    >
}

if ( EXISTS "A.txt" AND NOT EXISTS "B.txt" )
{
    <
        A.txt を使って B.txt を作成してください。
    >
}

if ( (EXISTS "A.txt" OR EXISTS "B.txt") AND NOT EXISTS "DONE.txt" )
{
    <
        存在する入力ファイルを処理してください。
    >
}
```

条件は `if` に到達した時点のファイルの有無に基づいて評価する。

`else`、`else if`、数値比較、文字列比較、Codex の応答内容による条件判定はサポートしない。複数の `if` はそれぞれ独立して評価される。

## 7. for

### 7.1 書式

```text
for i : 1...10
{
    <
        ${i} 番目の処理を実行してください。
    >
}
```

- 開始値と終了値は整数リテラルで指定し、両端を含める。
- 開始値が終了値より小さければ +1 ずつ、大きければ -1 ずつ変化させる。
- 開始値と終了値が等しければ1回実行する。
- 負数を指定できる。
- 刻み幅の指定、変数による範囲指定には対応しない。

| 範囲指定 | 反復する値 |
| --- | --- |
| `1...3` | 1, 2, 3 |
| `3...1` | 3, 2, 1 |
| `-2...2` | -2, -1, 0, 1, 2 |
| `5...5` | 5 |

各反復ではループ変数にその回の整数が設定される。プロンプト内の `${i}` はその値の文字列表現に置換される。

## 8. foreach

### 8.1 文字列を直接列挙する

```text
foreach name : "東京", "大阪", "名古屋"
{
    <
        ${name} について調べてください。
    >
}
```

- 値は二重引用符で囲んだ文字列リテラルとし、カンマで区切る。
- 記述順に1要素ずつ処理する。
- 空文字列 `""` も有効な要素とする。
- 次のエスケープシーケンスに対応する。それ以外のエスケープは構文エラーとする。

| 記法 | 展開される文字 |
| --- | --- |
| `\"` | 二重引用符 |
| `\\` | バックスラッシュ |
| `\n` | LF（改行） |
| `\r` | CR |
| `\t` | タブ |

このエスケープ規則は列挙値の文字列リテラルに適用し、`FILE` や `EXISTS` のパスには適用しない。

### 8.2 テキストファイルの各行を列挙する

```text
foreach name : FILE "names.txt"
{
    <
        ${name} について調べてください。
    >
}
```

例えば `names.txt` の内容が次の3行であれば、3回実行する。

```text
東京
大阪
名古屋
```

- `foreach` に到達した時点で対象ファイルの全行を読み込み、列挙値を確定させる。
- 読み込んだ行はファイルの記述順に処理する。
- 行末の改行コードは値に含めない。それ以外の空白は保持する。空行も空文字列の1要素とする。空ファイルの場合は0回実行する。
- 反復中にファイルが変更されても、現在の `foreach` の列挙内容は変わらない。
- 同じ `foreach` に再度到達した場合は、あらためてファイルを読み込む。
- `FILE` のパスに変数を埋め込むことはできない。

## 9. 変数展開

### 9.1 基本規則

- 変数は `for` と `foreach` のヘッダでのみ定義する。
- 変数名は `[A-Za-z_][A-Za-z0-9_]*` とし、大文字・小文字を区別する。
- 変数の有効範囲は、定義したループの `{ ... }` 内のみとする。
- 入れ子のループで同名の変数を宣言した場合は内側を優先し、内側のループを抜けると外側の変数が再び有効となる。
- **`${name}` による変数展開はプロンプトブロックの内部に限定する。**
- 未定義変数やスコープ外の変数を参照する場合は構文エラーとする。
- 制御構文内の変数参照（パス、範囲、列挙値など）は構文エラーとする。
- 展開結果を再解析、再展開しない。
- プロンプト内の `$${name}` は変数展開を行わず、文字列 `${name}` として扱う。
- 一般的な変数宣言、代入、配列、数値演算などはサポートしない。

### 9.2 有効な例

```text
foreach name : "東京", "大阪"
{
    for i : 1...3
    {
        <
            ${name} の ${i} 番目の観点を調査してください。
            結果を ${name}.txt に追記してください。
        >
    }
}
```

プロンプトの文章中でファイル名を組み立てることは可能である。組み立てたファイル名を `EXISTS` などの制御構文で直接参照することはできない。

### 9.3 無効な例

次の各例は構文エラーとなる。

```text
foreach name : "東京", "大阪"
{
    if ( EXISTS "${name}.txt" )
    {
        <
            ファイルを調べてください。
        >
    }
}
```

```text
foreach name : FILE "${filename}"
{
    <
        ${name} を処理してください。
    >
}
```

```text
for i : 1...3
{
    <
        ${i} を処理してください。
    >
}

<
    ${i} の結果をまとめてください。
>
```

最後の例では、ループの外側から変数 `i` を参照している。

## 10. session

### 10.1 基本書式

```text
session
{
    <
        東京の人口を調べてください。
    >

    <
        先ほど調べた人口を大阪と比較してください。
    >
}
```

- `session` の外側では、プロンプトごとに独立した新規 Codex セッションを使用する。
- `session` に入るたびに独立したセッションの範囲が開始される。最初のプロンプトで新規セッションを作成し、2つ目以降のプロンプトは同じセッションを再開する。
- ブロックを抜けるまで同じセッションを維持する。ブロックを抜けたセッションは以降のプロンプトに引き継がない。
- `session` の入れ子は禁止し、構文エラーとする。
- `session` 内でも `if`、`for`、`foreach` を使用できる。

### 10.2 ループとの組み合わせ

次の例では3回とも同じセッションを使用する。

```text
session
{
    for i : 1...3
    {
        <
            ${i} 番目の調査を行ってください。
        >
    }
}
```

次の例では反復ごとに新規セッションを開始し、各反復内の2つのプロンプトでセッションを共有する。

```text
foreach name : "東京", "大阪"
{
    session
    {
        <
            ${name} について調査してください。
        >

        <
            先ほどの調査結果を要約してください。
        >
    }
}
```

## 11. ファイル・フォルダの操作

### 11.1 delete

```text
delete C:\temp\CodexBatchTest\result.txt
delete "C:\temp\CodexBatchTest\一時フォルダ"
```

- 指定先がファイルならそのファイルを削除する。フォルダなら配下も含めて削除する。
- 指定先が存在しなければ何もしない。

### 11.2 resetdir

```text
resetdir C:\temp\CodexBatchTest
resetdir "C:\temp\My Data"
```

- 指定先にフォルダがなければ、新しいフォルダを作成する。フォルダがあれば配下ごと削除してから、同じパスに空のフォルダを作成する。
- 同じパスにファイルがある場合はエラーとする。
- 作成したフォルダは `writable` と同じ書き込み先に追加する。

### 11.3 writable

```text
writable C:\temp\CodexBatchTest
writable "C:\temp\My Data"
```

- 既存のフォルダを、同じスクリプトの後続の Codex 呼び出しで書き込める場所として追加する。`session` の再開時にも適用する。
- フォルダが存在しない場合はエラーとする。Windows の NTFS アクセス許可は変更しない。

3つのコマンドはそれぞれ独立した行に記述する。パスは第5節の書式に従い、空白などがなければ二重引用符を省略できる。ドライブや共有のルートは `delete` と `resetdir` の対象にできない。

## 12. 未対応の構文

次の構文はサポートしない。

- `else`、`else if`、`while`
- `break`、`continue`、`return`
- `try`、`catch`、`finally`、`throw`
- 関数定義、一般の変数宣言・代入、数値演算・比較
- プロンプト外の変数展開
- `session` の入れ子

## 13. 統合サンプル

先行するプロンプトで調査対象ファイルを生成し、存在を確認してから、その各行について調査する例。

```text
// 調査対象リストを作成する
<
    日本の興味深い観光地を3件選んでください。
    地名だけを1行ずつ names.txt に書いてください。
    ファイルはUTF-8 BOM付きで保存してください。
>

if ( EXISTS "names.txt" )
{
    foreach name : FILE "names.txt"
    {
        session
        {
            <
                ${name} について調査してください。
            >

            <
                先ほどの調査結果を SUMMARY.txt に追記してください。
            >
        }
    }
}

if ( EXISTS "SUMMARY.txt" )
{
    <
        SUMMARY.txt の内容を整理してください。
    >
}
```

この例では、調査対象の各行に対して新しい Codex セッションを使い、調査と追記の2つのプロンプトの間だけ文脈を共有する。最後のプロンプトは独立したセッションで実行される。
